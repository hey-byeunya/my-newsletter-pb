# 비교 실험

프롬프트나 스키마를 고치기 전에 재는 자리입니다. 이 프로젝트는 한 번 데었습니다 —
검수 프롬프트를 '개선' 하려다 오탐을 0/3 에서 3/3 으로 만들었고(REPORT.md 5-4절),
그 뒤로 절차가 생겼습니다.

> **고정 입력을 떠 둔다 → 정답을 손으로 붙인다 → 변형별로 여러 번 돌린다
> → 고치려던 것과 함께 망가질 수 있는 것도 잰다.**

마지막 조건이 핵심입니다. 검수 사고 때는 "환각을 더 잘 잡는가" 만 보고
"멀쩡한 것을 떨어뜨리지 않는가" 를 보지 않았습니다.

## 고정 입력과 정답표

`fixed_shortlist.json` — 2026-09-15 실행에서 예선을 통과한 **21건**을 그대로 뜬 것입니다.
후보가 매번 바뀌면 변형이 아니라 노이즈를 비교하게 되므로, 모든 변형이 같은 21건을 봅니다.

정답은 `_common.py` 에 손으로 붙였습니다.

| | 값 | 무엇 |
|---|---|---|
| `DUP_PAIRS` | `(5,6)` · `(10,11)` | 같은 사건을 다룬 쌍 — 성난사람들2 에미상, 문학동네 매각 |
| `BAD` | `{5, 6, 7}` | `버릴_것` 을 정면으로 어기는 것 — 전부 시상식 수상 발표 |

`BAD` 는 **보수적으로** 표시했습니다. 문학동네(10·11)처럼 애매한 것은 위반으로 세지 않았습니다.

## 돌리는 법

```bash
./.venv/bin/python experiments/exp_dup.py --detector-only   # LLM 안 씀 · 비용 0
./.venv/bin/python experiments/exp_drops.py --reps 6
./.venv/bin/python experiments/exp_k.py    --reps 5 --ks 16 12 10 8
./.venv/bin/python experiments/exp_dup.py  --reps 5
```

결과는 `results/` 에 쌓입니다. `--detector-only` 는 코드 검출기만 210개 쌍 전부에
돌리는 것이라 **키 없이도 즉시 재현**됩니다.

## 무엇을 쟀고 무엇이 나왔나

| 파일 | 고치려던 것 | 결과 | 코드에 반영? |
|---|---|---|---|
| `exp_drops.py` | 탈락 사유가 안 온다 | 설명을 조이면 **더 나빠진다**(49→29건). 스키마로 강제하면 100% | ✅ `Drop` |
| `exp_k.py` | 본선 요청 수가 너무 크다 | **가설이 틀렸다** — 줄이면 쿼터만 나빠진다 | ❌ 현행 유지 |
| `exp_dup.py` | 같은 사건이 안 묶인다 | 라벨로는 못 고친다. **12건이 1건이 될 뻔한 사고**도 발견 | ✅ `_near_dup` · `LABEL_MAX` |

세 번 중 **한 번은 "바꾸지 않는다" 가 결론**이었습니다.

## 알려진 한계

- **표본이 작습니다.** 고정 입력 21건, 정답쌍 2개, 변형별 5~6회입니다. 방향은 보이지만
  근소한 차이는 노이즈와 구분되지 않습니다. `exp_k.py` 의 K=16·12·10 차이가 그렇습니다.
- **`exp_k.py` 의 `assign()` 은 `select()` 를 손으로 옮긴 것**이라 원본과 갈라질 수 있습니다.
  실제로 지금은 근접 중복 검사가 빠진 상태(실험 당시 코드)를 재고 있습니다.
- **`exp_drops.py` 의 `has_reason()` 은 A·B 를 과대평가합니다.** 문자열에서 제목을 걷어낸
  나머지로 판정하는데 `(경향 문화)` 같은 출처 접두어가 사유로 오인됩니다. 첫 집계에서
  실제로 그랬습니다 — **숫자만 믿지 말고 원문도 보십시오.**
- **검수기(`check()`) 자체의 평가셋은 아직 없습니다.** 여기 있는 것은 전부 선별 단계입니다.
