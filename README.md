# 뉴스레터 에이전트

매일 아침 9시 50분, 문화·공간 소식 200여 건을 읽고 다섯 건을 골라 디스코드로 보냅니다.

볼 만한 것(스트리밍·극장·책)과 가볼 만한 곳(전시·건축)을 나눠 담습니다.

```
17곳 소스 ──① 수집──▶ 400여건 ──② 선별──▶ 8건 ──③ 취재──▶ 8건
 (국내8·해외9) 시간창·중복·상한   예선→본선       팬아웃(Send)
                                 (여유분)             │
              store/metrics.jsonl ◀── ⑤ 발행 ◀──── ④ 검수
                 (깔때기·소스별 기여)  쿼터·매체상한    LLM 대조
                                      → 최종 5건      (합격만 통과)
```

검수가 건수를 줄이므로 선별에서 여유분(8건)을 뽑고, **발행 직전에** 쿼터와
매체 상한을 다시 걸어 최종 5건을 확정합니다. 보장은 결과가 정해지는 자리에서
걸어야 합니다 — 앞에서만 걸었을 때 두 회차 연속 배분이 깨졌습니다.

## 파일

| 파일 | 무엇 | 고치는 사람 |
|---|---|---|
| `REPORT.md` | 제출 보고서 — 소스 채택표·선별 설계·실행 기록 | — |
| `graph.py` | 절차 — State·노드 다섯 개·그래프·run() | 개발자 |
| `run.py` | 진입점. 한 번 실행하고 로그를 찍는다 | 개발자 |
| `audience.yaml` | 독자·중요도 기준·버릴 것·토픽 | **편집 방향을 정하는 사람** |
| `settings.yaml` | 임계값과 소스 목록 | 개발자 |
| `source_audit.py` | 소스별 실측 — 접근·물량·본문 추출 (LLM 안 씀) | — |
| `report_card.py` | 쌓인 기록으로 소스 성적표 | — |
| `experiments/` | 프롬프트·스키마를 고치기 전에 재는 자리 | 개발자 |
| `.github/workflows/daily.yml` | 매일 아침 자동 실행 | 개발자 |
| `store/metrics.jsonl` | 실행마다 한 줄씩 쌓이는 기록 | (자동) |
| `store/source_cache.json` | 닿지 않는 곳에서 쓰려고 남겨 둔 수집 결과 | (자동) |

## 처음 한 번

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
cp .env.example .env        # OPENAI_API_KEY 와 DISCORD_WEBHOOK_URL 채우기
```

디스코드 웹훅은 `채널 톱니바퀴 → 연동 → 웹후크 → 새 웹후크 → URL 복사`.
**그 URL 자체가 비밀번호입니다.** 저장소에 올리지 마세요(`.env` 는 `.gitignore` 에 있습니다).

## 돌리기

```bash
./.venv/bin/python run.py --dry-run      # 보내지 않고 무엇을 보낼지만 출력 (기본)
./.venv/bin/python run.py --send         # 실제로 디스코드에 발행
./.venv/bin/python run.py --hours 48     # 시간 창을 이틀로
./.venv/bin/python report_card.py        # 쌓인 기록으로 성적표
```

`DRY_RUN` 기본값은 `1`(보내지 않음)입니다. 실수로 발행되는 쪽보다 실수로 안 보내는 쪽이 덜 나쁩니다.

## 자동 실행

1. 저장소 `Settings → Secrets and variables → Actions` 에 `OPENAI_API_KEY`, `DISCORD_WEBHOOK_URL` 등록
2. `Actions` 탭 → `매일 브리핑` → `Run workflow`, **dry_run 체크한 채로** 먼저
3. 로그가 정상이면 체크를 풀고 다시 실행
4. 내일 아침부터 자동

`cron: "50 0 * * *"` 는 **UTC** 기준이라 KST 09:50 입니다. 스케줄은 몇 분~한 시간 밀릴 수 있고,
60일 동안 커밋이 없으면 자동으로 꺼집니다.

## 내 분야로 옮기기

`audience.yaml` 과 `settings.yaml` 의 `sources` 만 바꾸면 됩니다. `graph.py` 는 건드리지 않습니다.

중요도 기준을 쓸 때 규칙 두 개:
- **기사 하나를 보고 예/아니오로 답할 수 있는 질문**으로 (✗ "좋은 기사인가")
- **추상어 말고 구체적으로** (✗ "홍보성" → ○ "MOU·투자유치·수상")

## 설계 메모

- **관문과 등급은 다른 것을 잰다** — 관문(본문·생존·접근)을 통과했다고 좋은 소스가 아닙니다. 기여도는 `report_card.py` 가 말해 줍니다.
- **개수가 고정된 문제는 정렬 문제다** — 독립 채점은 동점이 몰려 다섯 번째에서 자를 근거를 주지 못합니다. 그래서 예선→본선 상대평가입니다.
- **출력의 구조가 검증 가능성을 정한다** — `headline`·`summary` 는 원문과 대조할 수 있고 `why` 는 없습니다. 그래서 검수는 앞의 둘만 봅니다.
- **프롬프트는 요청이지 보장이 아니다** — "같은 사건은 하나만"은 부탁이라, `select()` 가 `event` 라벨을 코드로 셉니다. 한국어 출력도 `report()` 가 코드로 확인하고 한 번 재요청합니다.
- **펼칠 수 있는 단계와 없는 단계** — 기준은 "이 단계는 다른 항목을 봐야 답할 수 있는가". 선별은 봐야 하므로 모으고, 취재는 안 봐도 되므로 `Send` 로 펼칩니다.
- **못 채우는 날은 적은 대로 발행한다** — 되돌아가는 경로가 없으므로 재시도·비용 상한 설계가 통째로 필요 없습니다.
- **0건인 날에도 보낸다** — 아무것도 안 보내면 파이프라인이 죽은 것과 구분이 안 됩니다.
- **보장은 결과가 정해지는 자리에서 건다** — 쿼터를 선별에 걸어도 그 뒤 검수가 건수를 줄이면 무너집니다. 그래서 발행 직전에 한 번 더 겁니다.
- **쿼터는 바라는 비율이 아니라 채울 수 있는 양이다** — 늘 미달로 남는 목표는 신호를 주지 못합니다. 매 회차 `문화 1/3` 이 찍히면 이상한 날인지 보통 날인지 구분되지 않습니다. 실측 비율에 맞추면 미달이 다시 예외가 됩니다.
- **캐시는 신선한 척하지 않는다** — 캐시한 항목의 시각을 받은 때 그대로 둡니다. 그래서 시간 창보다 오래되면 수집에서 저절로 전부 탈락합니다 — 유효기간을 따로 두지 않아도 스스로 만료됩니다.
- **비밀값은 값 대신 '모양' 을 남긴다** — 자동 실행에는 보는 사람이 없고 `***` 로 가려져 무엇이 잘못됐는지 알 수 없습니다. 길이와 형태만 로그에 남깁니다.
- **`verify_fail` 이 0 인 것은 좋은 소식이 아닙니다** — 확인이 필요하다는 신호입니다. 가짜 숫자를 끼운 요약을 가끔 흘려보내 검수가 잡는지 보세요.

## 알려진 제약

- 국내 전시는 RSS 가 없어 공공 API(문화포털)로 올라갔는데, GitHub Actions 러너에서는 닿지 않습니다. 국내에서 돌릴 때 받아 둔 결과를 `store/source_cache.json` 에 남기고 **CI 는 그것을 읽습니다.** 전시는 몇 주씩 열리므로 하루 이틀 지난 목록도 쓸 만합니다. 캐시를 썼다는 사실과 나이는 로그에 남습니다.
- 본문 추출이 막히는 매체(Dezeen·RogerEbert·NYT Books)는 물량과 무관하게 탈락시켰습니다. 자세한 근거는 `REPORT.md` 의 소스 채택표에 있습니다.
- 프롬프트를 고칠 때는 **고정 입력 위에서 변형을 여러 번 돌려 비교**합니다 — `experiments/` 에 있습니다. 다만 아직 회귀 검사는 아닙니다(통과 문턱도, 자동 실행도 없습니다).
- 검수기 평가셋, 발행 전 사람 승인, 단계별 모델 배분은 아직 없습니다.
